# Design rules

These rules apply to every screen, and a PR that breaks one must say why.
The goal is an app that feels calm, specific and fast: you open it, see where you stand, and act in one tap.

## System

- **Design system:**
  - Components are **shadcn/ui** (Radix primitives) on Tailwind.
  - All colour, radius, spacing and type values come from tokens in `apps/web/src/styles/tokens.css`. No hex values or magic pixel values in components.
- **Spacing:**
  - Use a 4 px scale (4, 8, 12, 16, 24, 32, 48).
  - Group related things by **spacing, not boxes or dividers**: tight inside a group (8), loose between groups (24–32).
- **Radius:**
  - **Inner radius = outer radius − padding.** For example, a card with a 20 px radius and 12 px padding gives an inner element an 8 px radius.
  - Never use the same radius nested.
- **Icons:**
  - Only **Lucide**, at 20 px with a 1.75 stroke, outline style.
  - Don't mix filled and outline icons, and no emoji as icons.

## Colour

- **Neutrals** carry the UI. **One accent** (indigo, `--accent`) is used for the primary action, the current selection and focus. Nothing else uses it.
- **Semantic colours** have fixed meanings and are never used for decoration:
  - green: below average / on track;
  - red: above average, debt, a failed check;
  - amber: warm/unverified data, or something needs your attention.
- **Contrast:**
  - Body text must reach WCAG AA (4.5:1) and large numbers 3:1, in both light and dark themes.
  - Muted text is still readable. No light-grey-on-white.

## Type

- **Geist** (SIL OFL, bundled) is the text and numbers face: UI, labels, every amount.
- **PP Neue Montreal** is the display face: the net-position hero, screen headlines and the wordmark.
  - Its free licence covers personal use only and doesn't allow redistribution, so the files are never committed.
  - Builds load them from the gitignored `apps/web/src/fonts/licensed/` folder (CI gets them from a repository secret) and fall back to Geist when they're absent.
- **Geist Mono** is used only where the monospace rule below allows it.
- Season is not used: its sans–serif blend doesn't suit numeric UI, and it needs a paid licence.
- **Tabular figures everywhere money appears** (`font-variant-numeric: tabular-nums`), so columns and changing numbers don't jitter.
- **Monospace only where the content is code-like:** transaction IDs, the raw statement text in the import preview, IBAN fragments. Never for amounts or labels.
- **Headings:**
  - Use `text-wrap: balance`; no orphaned single words.
  - No italic or bold emphasis on random words in headings.
- **Headlines are specific.**
  - Write "Rs 18,400 on food — Rs 3,500 over your average", not "Food".
  - Write "Rs 42,500 in debt · clear by Mar 2027", not "Overview".

## Hierarchy

- **The main feature is the biggest thing on screen.** On Home that's the net position, centred: the largest type in the app, red in debt mode.
- **One primary CTA per screen.** It's filled with the accent; secondary actions are ghost or text buttons. Examples:
  - "Close November" on the close checklist;
  - "Import 2 statements" when files are found.
- **No redundant labels.** The value and its context speak for themselves:
  - write "Rs 500 · Danish · 7 Nov", not "Amount: Rs 500, Payee: Danish";
  - don't title a card "Food card".
- **No filler:** no badges like "New" or "Beta", no decorative gradients, glows, drop shadows, illustrations or ornamental dividers. Shadows only when something floats (sheets, menus).
- **Align by eye, not by box:**
  - optically align the `Rs` prefix, round icons and numerals, and nudge them when maths and perception disagree;
  - numbers in lists are right-aligned on the figures.

## Feedback and state

- **Loading:**
  - use skeletons shaped like the real content;
  - never show a blank screen or a layout jump;
  - only show a spinner inside a button the user just pressed.
  - Local data renders instantly, and sync happens quietly in the background with a small status dot.
- **Optimistic updates:** tagging, adding and closing reflect immediately. Errors roll back with an inline message that says what happened and what to do.
- **Animation is feedback, not decoration.** Use 150–250 ms ease-out, and switch it off under `prefers-reduced-motion`. Examples:
  - the balance figure counts to its new value after an import;
  - a tagged row settles into its category;
  - a warm transaction turns solid when a statement verifies it;
  - a check animates in when the month closes;
  - the what-if verdict changes colour as you type.
- **Empty states** say exactly what to do next, with the CTA, e.g. "Generate a SadaPay statement — it'll appear here automatically".

## Show the product

- READMEs, release notes and docs use **real screenshots of the app** (synthetic data), never mock illustrations.
- Screenshots are regenerated by the Playwright suite so they stay current.
